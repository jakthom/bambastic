# Automation and operations

[Product specification](../PRODUCT-SPEC.md) · [Related access and interfaces](access-and-interfaces.md)

A farm combines devices that report status, devices that can switch physical equipment, and integrations that can only observe. Bambuddy lets an operator connect these independently. A printer's electricity meter, enclosure fan, door sensor, empty-plate camera and maintenance clock all answer different questions about the same machine. [Smart plug model](../../bambuddy/backend/app/models/smart_plug.py) · [Printer sensors](../../bambuddy/backend/app/models/printer_ha_sensor.py) · [Farm sizing](https://wiki.bambuddy.cool/reference/farm-sizing/)

## Power, meters and environmental sensors

| Adapter | Capabilities and restrictions |
| --- | --- |
| Tasmota | Query and switch a network plug and read meter values where the device provides them. Configure host and optional device credentials. [Tasmota adapter](../../bambuddy/backend/app/services/tasmota.py) |
| Home Assistant | Bind a switch or supported action/script. Power, daily energy and lifetime energy can come from separate HA sensor entities. A script is a trigger, so a scheduled switch-off and a forced power cut must skip it. [HA adapter](../../bambuddy/backend/app/services/homeassistant.py) · [Plug capability checks](../../bambuddy/backend/app/services/smart_plug_manager.py) |
| REST / webhook plug | Configure on/off requests, method, headers/body and optional status, power and energy endpoints. Extract values using paths and unit multipliers. Today's counter and the lifetime counter can be different fields in the same response. [REST adapter](../../bambuddy/backend/app/services/rest_smart_plug.py) |
| MQTT meter | Subscribe to configured topics for state, power and energy, optionally using different fields and multipliers. It is monitor-only in the tagged implementation. Meter readings can contribute to statistics without giving the scheduler a usable power switch. [MQTT meter](../../bambuddy/backend/app/services/mqtt_smart_plug.py) · [Plug guide](https://wiki.bambuddy.cool/features/smart-plugs/) |

**Power ownership.** Several plugs can follow one printer's print cycle. A flag identifies a plug that actually powers the printer. Only a genuine power feed can cause the application to mark the printer offline when it cuts power. Show observed state, last check, reachability and quick controls, respecting device scope and control permissions. Schedule on/off times and optionally run associated scripts. Out-of-range power warnings consider reachability, actual on/off state and a cooldown, so a powered-off printer doesn't constantly produce a low-wattage alarm. [Smart plug manager](../../bambuddy/backend/app/services/smart_plug_manager.py) · [Power alerts](../../bambuddy/backend/app/services/power_alerts.py)

**Automatic shutoff.** A successful print can arm auto-off, either after a time delay or when the hottest reported nozzle falls below the configured threshold. A failed print leaves ordinary completion-driven power on for inspection. A queue item's auto-off option and an AMS drying-complete option have their own triggers. Distinguish one-shot and persistent preferences. Persist a pending cutoff and its time for recovery, expire stale requests, cancel a pending cutoff on a new print even when auto-on is disabled, and check again before acting on a busy machine. Pausing on an AI alert with an explicit power-off policy is a separate action. [Timer and restart behavior](../../bambuddy/backend/app/services/smart_plug_manager.py) · [AI action handler](../../bambuddy/backend/app/services/obico_actions.py)

**Per-run energy.** Read a real meter at start and end. Rank enabled meter candidates, favoring plugs marked as powering the printer, and skip non-metering devices. Persist the starting value and enough source/time information for a backend restart. Treat watts as instantaneous power and kWh as cumulative energy. A counter reset or missing reading changes the reliability of a delta. An unknown energy result should remain distinguishable from a measured zero. [Meter selection](../../bambuddy/backend/app/services/energy_plug.py) · [Run energy capture](../../bambuddy/backend/app/main.py) · [Meter selection tests](../../bambuddy/backend/tests/unit/test_energy_plug_selection_2859.py)

**Cost over time.** The statistics view can show per-print consumption or total plug consumption including idle time. Store hourly lifetime-counter samples, price per kWh and running cost totals. A fixed rate, a pushed tariff or a Home Assistant price entity can supply the price. Normalize price units, retain a usable fallback, and price each positive counter interval at its starting rate. For example, a meter advances from 10 to 11 kWh at 0.10 per kWh, then from 11 to 13 at 0.25. The 3 kWh cost 0.60. A subsequent price change does not reprice that history. Use local day boundaries for daily figures. These electricity costs have a different policy from wallet settlement. [Rate calculation](../../bambuddy/backend/app/services/energy_price.py) · [Counter history](../../bambuddy/backend/app/services/plug_energy_history.py) · [Energy guide](https://wiki.bambuddy.cool/features/energy/)

**Home Assistant sensor bindings.** A printer can display multiple read-only binary or numeric entities with native labels/units and configurable alert conditions. Poll on a 15-second cadence, offer a notification on transition and optionally use the condition as a dispatch hold. A reachable, alerting interlock holds the queued job until it clears. An unavailable sensor is shown as unknown and does not block dispatch in this release. It is an operational convenience, unsuitable as the sole input for a machine safety interlock. Last known state and current reachability are separate. A dropout between two identical alarming readings must not reannounce the same edge. Storage-location sensors monitor dryboxes/shelves, support threshold alerts and selectable display on filament cards, and use their own default 120-second poll interval (minimum 60 seconds). They have their own notification switch. [Printer poller](../../bambuddy/backend/app/services/ha_sensor_manager.py) · [Location poller](../../bambuddy/backend/app/services/location_ha_sensor_manager.py) · [Sensors guide](https://wiki.bambuddy.cool/features/sensors/)

**WLED.** Associate a controller with a printer, test its connection, load saved presets, and map printer states to preset numbers. Apply the first applicable state with a configured preset, prioritizing offline, filament runout, HMS fault and waiting for plate clearance before ordinary machine state. For example, a runout can fall back to the paused preset. An optional finished timer returns to idle unless state has already changed. Deduplicate sends and isolate retries to the controller. Legacy printer state continues to update through an LED outage. [State mapping and timers](../../bambuddy/backend/app/services/wled.py) · [WLED guide](https://wiki.bambuddy.cool/features/wled/)

## Detection and operator decisions

| Workflow | Evidence, decision and effect |
| --- | --- |
| Bed clearance and visual obstruction | Before dispatch, the scheduler can hold the next job until an operator confirms the bed is clear. When the printer subsequently reports a start, the optional visual check compares a new camera image with calibrated empty-bed references. A detected obstruction triggers a pause command and an alert. A missing reference or a capture error raises a separate check-failed event and the print proceeds. [Scheduler](../../bambuddy/backend/app/services/print_scheduler.py) · [Print-start callback](../../bambuddy/backend/app/main.py) · [Plate detector](../../bambuddy/backend/app/services/plate_detection.py) |
| Obico during a print | The local server captures a frame and makes it briefly available for the configured ML service to fetch. The ML service must be able to reach that URL. A recent per-print baseline, a longer per-machine baseline and a 30-frame warmup filter transient noise. The warning threshold can trigger notification. The higher failure threshold can trigger pause, or pause with power-off when selected. One action is latched per observed print. Pausing and resuming the same print preserves that latch. [Detection loop](../../bambuddy/backend/app/services/obico_detection.py) · [Signal and decision](../../bambuddy/backend/app/services/obico_smoothing.py) |
| OctoEverywhere Gadget during a print | Configure an API key, confidence, inspection interval, selected printers and action. Send captured images to the external service over HTTPS. Track its quality reading, warning and pause suggestions, minimum interval, retry timing and current print identity. Ignore stale responses from the prior run. Repeated warnings can notify again after three hours, while a configured physical intervention acts once per monitored run. When both provider flags are present, the Obico loop yields to OctoEverywhere. [Gadget integration](../../bambuddy/backend/app/services/octoeverywhere_detection.py) · [Obico selection](../../bambuddy/backend/app/services/obico_detection.py) · [Detection guide](https://wiki.bambuddy.cool/features/failure-detection/) |
| Physical action and operator outcome | Configure notify, pause, or pause-and-off. The last option attempts pause and turns off eligible enabled linked plugs. Report the event through selected channels, with an available image. A detection suggestion, a printer-reported failed job and a user's reject verdict are separate observations. The retrospective Failure Analysis page uses recorded print outcomes and other recorded attributes. [Physical action](../../bambuddy/backend/app/services/obico_actions.py) · [Outcome application](../../bambuddy/backend/app/services/print_confirmation.py) · [Retrospective analysis](assets-and-slicing.md) |

Detection depends on a reachable camera and provider. Show test/status and recent observations, distinguish no active print, no frame, rejected credentials and upstream throttling, and let work continue under the operator's chosen policy. On a larger fleet the unattended cost is the number of active inspected cameras as well as the number of human viewers. [Camera acquisition](../../bambuddy/backend/app/services/failure_detection_camera.py) · [Failure detection settings](https://wiki.bambuddy.cool/features/failure-detection/) · [Farm guide](https://wiki.bambuddy.cool/reference/farm-sizing/)

## Notifications and operator feedback

- An administrator defines named providers, credentials, enabled state, printer filter, event toggles, quiet hours, photo preference, test delivery and optional digest time. The release implements WhatsApp via CallMeBot, ntfy, Pushover, Telegram, email, Discord, generic webhooks, Home Assistant, Bark, Gotify and Notify!. Per-provider priority, image, topic/thread and action support varies. Templates map event variables to subject/body, support preview/reset and fall back to defaults. Store send status, event, printer, time and error so a failed channel is visible. [Provider schema](../../bambuddy/backend/app/schemas/notification.py) · [Templates](../../bambuddy/backend/app/api/routes/notification_templates.py) · [Delivery](../../bambuddy/backend/app/services/notification_service.py)
- Triggers include starts, completion/failure/stop, progress milestones, upcoming pause, first layer, bed cooled, device offline/HMS errors, unassigned or low filament, stock reorder or shortage, AMS humidity/temperature/drying, sensor threshold crossing, plate-clear, AI detection, maintenance, queue transitions, failed billing and application messages. A system-wide inventory event has no printer ID. Scope and delivery decisions must respect whether an event belongs to a particular printer or the installation. Avoid repeating a persistent fault on every status report. [Event flags and digest/log rows](../../bambuddy/backend/app/models/notification.py) · [HMS fault state](../../bambuddy/backend/app/services/hms_notified.py) · [Scope tests](../../bambuddy/backend/tests/integration/test_notification_scope_without_printer.py)
- Quiet hours can cross midnight. Routine immediate deliveries inside the quiet window are suppressed. The digest is an additional provider-level summary of selected events, including ones suppressed from immediate delivery. At its chosen time it can send even during quiet hours. A failed digest retains eligible events for a subsequent attempt with bounded retention. An ordinary delivery failure is logged. Each destination's success is independent. [Delivery and digest scheduler](../../bambuddy/backend/app/services/notification_service.py) · [Operator settings](https://wiki.bambuddy.cool/features/notifications/)
- Support photo bytes, an externally reachable short-lived photo link or inline email attachment according to channel and event. The attach-photo toggle applies separately to each provider. Telegram can target forum topics. ntfy and Telegram support responding good/reject through their supported affordances. A link preview must not record a verdict. Button/reaction handling resolves the intended run and entitlement. Notify! can maintain one live progress activity and persistent status widgets with provider cleanup. Personal email preferences deliver eligible events for the user's own prints under the configured permission. [Photo and verdict dispatch](../../bambuddy/backend/app/services/notification_service.py) · [Telegram reactions](../../bambuddy/backend/app/services/telegram_reactions.py) · [Live activities](../../bambuddy/backend/app/services/notify_live_activities.py) · [Widgets](../../bambuddy/backend/app/services/notify_widgets.py) · [Personal preferences](../../bambuddy/backend/app/api/routes/user_notifications.py)

## Maintenance, firmware and system administration

**Maintenance.** Provide a shared catalog of default and custom tasks, per-printer assignment/disable and interval overrides. Some defaults depend on model. Track either calendar days or operating hours. Operating hours are the printer's accumulated running seconds divided by 3,600 plus a baseline offset. Pausing a machine for an hour doesn't use an hour of mechanical maintenance interval. Report due, due soon (within the final 10% of the interval) and remaining hours/days. Marking a task performed records a time, hour reading, note and actor and resets the interval. The maintenance log snapshots names for records that outlive their printer, user or task and supports filtered history, CSV and authorized cleanup. Taking a printer out of service for maintenance affects scheduling separately. [Maintenance catalog, calculations and routes](../../bambuddy/backend/app/api/routes/maintenance.py) · [Historical records](../../bambuddy/backend/app/models/maintenance.py) · [Maintenance guide](https://wiki.bambuddy.cool/features/maintenance/)

**Firmware.** Compare the connected device's reported version with announced model-specific releases when firmware checks are enabled. Distinguish installed, downloadable package and announced release without a downloadable package. Present version, release notes, prerequisites and transfer progress. For a chosen usable version, check connected/idle state and storage, cache the official package, recheck busy state after download and upload to printer storage. Support selecting an older usable version. Completion of transfer means the operator can initiate installation on the printer's own screen. Keep progress and errors per printer and coordinate storage access with print dispatch. [Firmware check](../../bambuddy/backend/app/services/firmware_check.py) · [Preparation and transfer](../../bambuddy/backend/app/services/firmware_update.py) · [Firmware guide](https://wiki.bambuddy.cool/features/firmware-updates/)

**Settings and health.** The application distinguishes installation settings, per-user preferences, per-printer overrides and per-job choices. Examples include server timezone/external URL, currency/tariff, archive/media retention, port/mount configuration, job defaults, UI density and language. The system page exposes version, uptime, runtime environment, CPU/memory/disk, data usage, database type/pool and a log-based health scan. Diagnostic probes distinguish MQTT, file transfer and camera problems. Debug logging, log tail/download, a sanitized diagnostic bundle and an opt-in bug report with optional screenshot/support information are distinct workflows. Local diagnosis and submitting a report to the upstream relay have different data destinations. [System routes](../../bambuddy/backend/app/api/routes/system.py) · [Support bundle](../../bambuddy/backend/app/api/routes/support.py) · [Bug report](../../bambuddy/backend/app/api/routes/bug_report.py) · [System guide](https://wiki.bambuddy.cool/features/system-info/)

**Updates and notices.** Check application releases, honor the prerelease setting, show progress/failures and use the appropriate mechanism for source installs, containers and native Windows installations. The optional maintainer feed verifies a signed announcement, applies audience/version/channel criteria locally, keeps the last good list when fetching fails and tracks read state. A feed withdrawal removes a previously displayed notice. The sponsor prompt has a separate local milestone/dismissal record. [Application updater](../../bambuddy/backend/app/api/routes/updates.py) · [Announcements](../../bambuddy/backend/app/services/announcements.py) · [Sponsor state](../../bambuddy/backend/app/services/sponsor_prompt.py)

## Installation, storage and recovery

| Operating concern | Product contract |
| --- | --- |
| Deployment | The core supports container deployment, native Linux/macOS installation and a Windows installer. Keep code and static assets separate from persistent data and logs. Upstream Bambuddy serves the UI/API on port 8000 by default. LAN discovery and slicer-facing virtual printers have their own network requirements. Docker host networking and explicit bridge address/port mappings are different configurations. External library roots and NAS backups need mounts visible to the process. Preserve external locations as configuration and check reachability after a move. ### Backup products have different contents

**Full portable snapshot.** Manual download and scheduled local backup create ZIPs containing a SQLite-form database (also when exported from PostgreSQL), version manifest, and available files from `archive` (including the managed library), `virtual_printer`, `plate_calibration`, `icons`, `projects` and `overlay-branding`. Include the file-based MFA encryption key when present. An environment-supplied key requires continuity outside this file list. Externally indexed shares and remote services need their own data protection. Scheduled backup supports hourly/daily/weekly operation, local time, output-path probe, retention, history/listing, download and restore. Prune older snapshots after creating a new one. [ZIP writer](../../bambuddy/backend/app/api/routes/settings.py) · [Local backup service](../../bambuddy/backend/app/services/local_backup.py) · [Path probe](../../bambuddy/backend/app/services/backup_path.py)

**Full restore.** Validate the ZIP, required database and, for a PostgreSQL import, version/schema compatibility before committing a replacement. Quiesce device/dispatch and relevant timer work, release connections and use the SQLite online backup mechanism or transactional PostgreSQL import with type/ID/constraint handling. Normalize existing relative Windows paths where needed. The tagged restore clears directory contents before copying when that directory exists in the ZIP. It leaves an absent directory alone and can report skipped directories. Thus an empty source directory omitted by the tagged writer cannot clear destination-only files. Restoring data invalidates prior user sessions, refreshes access scopes and calls for an application restart. Database replacement and copying multiple file trees have different failure boundaries. The result must expose partial filesystem restoration. [Restoration implementation](../../bambuddy/backend/app/api/routes/settings.py) · [Path conversion](../../bambuddy/backend/app/services/backup_paths.py) · [Compatibility tests](../../bambuddy/backend/tests/unit/test_restore_schema_compat.py) · [Backup guide](https://wiki.bambuddy.cool/features/backup/)

**Git configuration/history backup.** Supports GitHub, GitLab, Gitea and Forgejo. Configure repository, branch, credentials, categories and frequency. Run manually or on schedule, skip an unchanged commit and keep a result log. Categories cover K-profiles by printer, custom cloud presets by provider/account, selected app settings, spool inventory/usage and archive/run metadata. Binary archive media are outside this format. Restore previews a selected commit and available categories, applies the corresponding domain write permissions in addition to restore permission, and reports restored/skipped/failed items. Credentials and protected settings have special treatment. K-profiles need a connected device and overwrite their destination slots. Cloud profile backup is available for reference/export and has no matching restore category in this release. [Git backup](../../bambuddy/backend/app/services/github_backup.py) · [Selective restore](../../bambuddy/backend/app/services/github_restore.py) · [Category permissions](../../bambuddy/backend/app/api/routes/github_backup.py)

## Acceptance examples

1. An operator finishes a successful print with temperature-based shutoff armed. The second nozzle on a dual-nozzle machine is still above threshold. Power remains on. Starting a second print before cooldown cancels the old timer.
2. An enclosure door enters its configured alert state. Send one alert and hold that printer's pending work. A reachable cleared reading makes it eligible again. An HA outage shows unknown with the release's documented nonblocking policy.
3. An unattended wall and an operator request the same live feed. Closing one client leaves the other working. An unreachable LED controller does not stall telemetry, print scheduling or camera teardown.
4. Obico reports a suspect image during warmup. The printer continues. A later sustained failure triggers the configured response once. For Gadget, a late pause suggestion for a completed job cannot pause its successor.
5. Send a scoped completion event to two enabled providers, one in quiet hours. The unrestricted channel receives the immediate message. The quiet channel can include it in the scheduled digest. A failed digest send can be retried without replaying a physical print action.
6. Restore a Windows-created portable backup to a temporary Linux installation. Verify archive/run media, relative paths, group and printer access, spool history and balances. An admin must sign in again. Check separately that an external library mount and any environment-managed encryption key are available.
7. Preview a Git backup containing cloud profiles, spools and history. Select only inventory and supply the required permissions. Restore the visible records and their usage using the configured match/overwrite policy. Expose per-category results and preserve other categories.
