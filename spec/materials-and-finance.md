# Materials, replenishment and billing

[Product specification](../PRODUCT-SPEC.md) · [Related print lifecycle](print-lifecycle.md)

A print uses a physical spool through a particular feed path. The slicer describes filament slots on one plate, the printer reports trays and tool changes, and inventory identifies the rolls that occupied those trays. Bambuddy joins those facts to debit stock. The print log records what a run used, while the finance ledger charges the responsible user or cost center under a separate policy. A replacement can reproduce either calculation only if it preserves the inputs to both. [Usage tracker](../../bambuddy/backend/app/services/usage_tracker.py) · [Finance settlement](../../bambuddy/backend/app/services/finance_billing.py)

## Inventory and its two storage modes

| Concept | Identity and behavior |
| --- | --- |
| Physical spool | One roll has a stable ID in its inventory backend. Two identical rolls can have different weights, tags, assignments, purchase prices and histories. The native record carries material, subtype, brand, color, RGBA, optional multicolor stops and effect, label and core weights, category, article number, note, cost/kg, presets and dates. Historical usage survives deletion with a nullable spool reference. Native IDs are never recycled. [Spool](../../bambuddy/backend/app/models/spool.py) · [Usage history](../../bambuddy/backend/app/models/spool_usage_history.py) |
| Product and supplier | Forecasting groups rolls by material, subtype, brand and color name. An internal material number can span several spools. A newly created native spool can inherit the most recently touched matching product's number, including from archived stock. A supplier is a separate entity with its own customer number. A spool can have several supplier links, supplier article numbers and quoted prices, with a purchase-source marker. The spool's cost/kg remains the actual costing input. [Material-number rules](../../bambuddy/backend/app/services/material_number.py) · [Suppliers](../../bambuddy/backend/app/models/supplier.py) |
| Catalogs | An empty-spool catalog supplies tare weights. A color catalog associates manufacturer, material, color name/code and display properties. Both support editing and reset. Colors support lookup, search, palette import via the UI and progress reporting on sync from FilamentColors.xyz. A separate filament catalog offers CRUD, seeded material defaults and a grams-times-price/kg calculator. It has no physical stock identity. [Inventory endpoints](../../bambuddy/backend/app/api/routes/inventory.py) · [Color catalog UI](../../bambuddy/frontend/src/components/ColorCatalogSettings.tsx) · [Filament endpoints](../../bambuddy/backend/app/api/routes/filaments.py) |
| Storage location | A shelf, drawer or drybox has a case-insensitively unique name and spool counts. Legacy free-text names are reconciled into the catalog. Operators can filter by location, rename it across spools and attach Home Assistant sensors with thresholds. A name in use cannot be deleted. This location coexists with the printer's location for access control and the spool's current AMS slot. In Spoolman mode physical storage maps to the remote spool's location text. [Location handling](../../bambuddy/backend/app/services/location_service.py) · [Location endpoints](../../bambuddy/backend/app/api/routes/inventory.py) · [Storage guide](https://wiki.bambuddy.cool/features/storage-locations/) |
| Slot assignment | A printer ID, AMS unit ID and local tray ID identify a place. One assignment occupies that key in the active inventory mode. A slicer filament ID, global tray ID, chip UID, Bambu tray UUID, spool ID and hotend ID each have different meanings. [Native assignment](../../bambuddy/backend/app/models/spool_assignment.py) · [Spoolman assignment](../../bambuddy/backend/app/models/spoolman_slot_assignment.py) · [Tray layout](../../bambuddy/backend/app/utils/tray_ids.py) |

**Native mode** stores spools, quantities and assignments in Bambuddy. **Spoolman mode** operates on remote vendors, filament definitions and spools through Spoolman's API. Bambuddy still owns the slot map, per-run history and several spool-specific extensions, including per-hotend K profiles and supplier links. The UI presents both through the Inventory page. Switching modes preserves each inventory's assignment rows. Reads for current slot configuration, weighing and NFC follow the active backend. A Spoolman outage cannot justify updating a native spool that happens to have the same number. [Mode selection](../../bambuddy/backend/app/services/inventory_mode.py) · [Spoolman mapping](../../bambuddy/backend/app/api/routes/_spoolman_helpers.py) · [Spoolman inventory](../../bambuddy/backend/app/api/routes/spoolman_inventory.py) · [Spoolman guide](https://wiki.bambuddy.cool/features/spoolman/)

An operator can create, copy, quick-add, bulk-create 1–100 rolls, edit selected fields across rolls, archive, restore and delete. Quick Add captures stock before a printer preset is known. Search by material, brand, color or name, or use `#<id>` for an exact match. The inventory offers table and card views, active/archived/all filters, new/used and stock/configured filters, and grouping of similar unused, unassigned rolls. An archived spool leaves its slot and drops out of active stock. Restoring makes it available for assignment again. Spoolman's bulk operations can partially succeed and return individual errors. Inventory read, mutation, assignment visibility and forecast permissions are independent. [Inventory UI](../../bambuddy/frontend/src/pages/InventoryPage.tsx) · [Native operations](../../bambuddy/backend/app/api/routes/inventory.py) · [Spoolman operations](../../bambuddy/backend/app/api/routes/spoolman_inventory.py) · [Inventory guide](https://wiki.bambuddy.cool/features/inventory/)

For native stock, remaining grams are the nonnegative difference between the advertised net weight and accumulated usage. The resettable consumption counter uses a separately stored baseline. Resetting the counter preserves physical remaining stock. Hand entry or weighing locks the native weight against routine AMS estimates. Print usage still adds grams to the stored value. An explicit AMS weight sync can correct in either direction and release the lock. It skips disconnected printers, invalid percentages, printers still printing and printers whose completion debit is in flight. In Spoolman, initial spool weight takes precedence over the filament's catalog size. Tare resolves from the spool, filament, vendor, then a 250 g fallback. A recorded zero tare is meaningful. ## Loading, recognizing and configuring material

1. **Identify the slot.** Ordinary four-slot AMS units use a different global numbering convention from AMS-HT single-slot units, A2L AMS Lite and nine-position H3C racks. External holders have stored slot indices under AMS ID 255. An observed `tray_now=255` usually means unloaded, but can identify a second external holder on some dual-holder models. Resolve against the actual unit and external-tray layout. Retain the slicer's one-based slot positions, including gaps. [Tray conversion](../../bambuddy/backend/app/utils/tray_ids.py) · [External-holder interpretation](../../bambuddy/backend/app/services/usage_tracker.py)
2. **Identify the roll.** Operators can choose a spool manually, create from a loaded slot, scan a label or recognize a tag. Prefer a meaningful Bambu tray UUID, then the chip UID. Normalize supported historical representations, discard blank/all-zero identifiers and avoid ambiguous partial-UID matches. A collision on explicit tag linking returns a structured conflict naming the holder. Tag-capable Spoolman versions support native tags alongside the legacy extra field and a migration action. Unknown RFID rolls can auto-create inventory with material/color/preset/weight metadata. With auto-add disabled, prompt once for an observed insertion so the operator can link existing stock. [Tag matcher](../../bambuddy/backend/app/services/spool_tag_matcher.py) · [Tag conflicts](../../bambuddy/backend/app/services/tag_conflict.py) · [Spoolman tag routes](../../bambuddy/backend/app/api/routes/spoolman_inventory.py) · [Unknown spool dialog](../../bambuddy/frontend/src/components/UnknownSpoolModal.tsx)
3. **Assign or move.** Ordinary assignment replaces the occupant at the target. An explicit physical move also vacates this spool's previous slots within the actor's printer scope. A failed native move rolls back both changes. Keep scope checks, serialize competing writes and broadcast updated slots after commit. Unassigning removes the tracking link. Configuring an untracked tray sets its printer metadata without creating a roll. Scanning to a storage location changes the shelf even if the spool has a slot assignment. [Assignment contract](../../bambuddy/backend/app/schemas/spool.py) · [Assignment routes](../../bambuddy/backend/app/api/routes/inventory.py) · [Scan targets](../../bambuddy/frontend/src/utils/qrAssignTarget.ts)
4. **Apply the configuration.** Assigning an occupied slot can publish its color, material, temperature range, preset and compatible pressure-advance calibration. Choose a filament preset by printer model and nozzle diameter, then model-wide override, then the spool's own value. A deliberately blank matching override can clear the preset. K selection depends on the actual printer, routed extruder, nozzle diameter and matching standard/high-flow information where available. Shared product defaults merge all-colors and color-specific entries and fill missing values on the spool. Explicit operator entries survive reapplication. [Preset resolution](../../bambuddy/backend/app/services/spool_filament_preset.py) · [Hotend resolution](../../bambuddy/backend/app/services/slot_nozzle.py) · [K profile lookup](../../bambuddy/backend/app/services/slot_kprofile.py) · [Product defaults](../../bambuddy/backend/app/services/filament_profile_default.py)
5. **Reconcile what the hardware reports.** A preassignment to an empty or disconnected slot persists with configuration pending. The next suitable insertion/report can replay it. Prefer an explicit firmware presence bit to a stale cached tray state. A temporarily blank fingerprint on a populated slot is weak evidence. Automatic unlink waits for an empty reading to persist for 120 seconds and treats contradictory identity or an explicit operator change separately. The Spoolman manual sync can remove a confirmed empty slot immediately, while protecting a printing machine from a transient runout. It supports manual and automatic sync, skipped-slot reasons and optional suppression of AMS estimated-weight writes. [Presence rules](../../bambuddy/backend/app/services/ams_slot_presence.py) · [Unlink grace](../../bambuddy/backend/app/services/slot_unlink_grace.py) · [Spoolman sync](../../bambuddy/backend/app/api/routes/spoolman.py)

The queue's material check joins the selected plate's required grams and planned tray mapping to the active inventory. With filament backup enabled it can pool recognized equivalent stock on the same extruder, including eligible backup spools outside the initial mapping. A known shortage can hold dispatch or disqualify an otherwise suitable printer. Unknown remaining weight generally permits the ordinary check to proceed. Callers that explicitly require known quantities get an unknown-amount result. [Deficit calculation](../../bambuddy/backend/app/services/filament_deficit.py) · [Scheduler integration](../../bambuddy/backend/app/services/print_scheduler.py)

## From print telemetry to stock and cost

| Stage | Behavior a port needs to reproduce |
| --- | --- |
| Print start | Snapshot the selected plate, run identity, slicer-to-tray mapping, assignments at start, starting tray and valid remaining percentages. Record subsequent tray switches and spool replacements with layer numbers. Native tracking persists an in-flight context per printer. The Spoolman tracker keeps the printer/archive context, tray identities, optional per-layer usage and filament properties. Recover the matching session after a restart. A new run must supersede stale context. [Native session](../../bambuddy/backend/app/models/active_print_session.py) · [Spoolman session](../../bambuddy/backend/app/models/active_print_spoolman.py) |
| Resolve the plate and mapping | Prefer the source for this run and extract the selected plate's usage by slicer slot. If the session lacks a plate, its dispatching queue row can identify it even when a different plate of the same archive ran elsewhere. A persisted dispatch or captured slicer mapping carries more information than the printer's end-of-print state. Other evidence includes a live mapping, unambiguous color matching, active-tray observations for single-filament jobs and, ultimately, position. Mappings containing only unused sentinels supply no evidence. A positional guess is observable in logs. [Native resolver](../../bambuddy/backend/app/services/usage_tracker.py) · [Spoolman resolver](../../bambuddy/backend/app/services/spoolman_tracking.py) |
| Completed run | Debit each used filament's slicer-estimated grams against its physical roll. Several slicer slots can consume from one tray. A tray handled through the 3MF path must be excluded from the fallback path. Identity can come from the start snapshot even after firmware retracts or clears the tray. In Spoolman mode resolve tag information or local assignment, submit remote usage, and record local per-print history with a distinctly named Spoolman spool ID. [Native attribution](../../bambuddy/backend/app/services/usage_tracker.py) · [Spoolman attribution](../../bambuddy/backend/app/services/spoolman_tracking.py) · [Usage row](../../bambuddy/backend/app/models/spool_usage_history.py) |
| Interrupted run | For failure or cancellation, use the fraction each filament actually extruded through the last valid layer, normalized against its sliced total where available. When layer data is missing, use last valid progress to scale the estimate. Firmware can zero current layer and percentage on cancel. Spoolman partial usage reporting can be disabled. A partial run can consume stock even if it delivers zero usable parts. [3MF calculations](../../bambuddy/backend/app/utils/threemf_tools.py) · [Tracker](../../bambuddy/backend/app/services/usage_tracker.py) · [Spoolman tracker](../../bambuddy/backend/app/services/spoolman_tracking.py) |
| Spool changed during a run | For a one-filament print where AMS backup switches trays, allocate grams across the observed feeding intervals. A different roll assigned to the *same* tray creates a separate layer-stamped change record. Divide that tray's grams by its extruded fractions, falling back to layer intervals. A first assignment to a previously unassigned tray accounts for the print from the beginning. In v.1.3.2, a multi-filament print uses its recorded mapping for cross-tray attribution. Its tray log alone cannot distinguish ordinary tool changes from a backup switch. [Tray splits](../../bambuddy/backend/app/utils/tray_split.py) · [Spool replacements](../../bambuddy/backend/app/services/spool_swaps.py) · [Routing at completion](../../bambuddy/backend/app/services/usage_tracker.py) |
| Missing slice data | For otherwise uncovered trays with comparable valid readings, turn a positive drop in remaining percentage into grams using the roll's net size. Where used-tray evidence exists, exclude other trays. A replacement between readings makes that difference unusable. A flat/rising percentage, unknown roll or absent telemetry can leave zero attributable usage. Warn or record missing attribution as appropriate. [Native fallback](../../bambuddy/backend/app/services/usage_tracker.py) · [Spoolman fallback tests](../../bambuddy/backend/tests/unit/test_spoolman_no3mf_remain_fallback.py) |
| Persist results | Native stock uses a database increment to preserve concurrent manual or scale writes. Record roll, printer, archive if known, grams, status, date and cost. Preserve historical cost after deleting a spool or archive. Spoolman's remote decrement and Bambuddy's history write occur in separate systems. A remote success followed by a local failure can leave the two histories out of step. [Native update race tests](../../bambuddy/backend/tests/unit/test_usage_tracker_charge_race.py) · [Spoolman tracking](../../bambuddy/backend/app/services/spoolman_tracking.py) |

A native spool's priced usage is grams × cost/kg ÷ 1,000, with the configured default when no price was supplied. Spoolman can price a spool from its purchase price divided by its own full net weight, or the filament's catalog price divided by its catalog weight. A remote zero price is treated as unset. A partially priced archive can fill the uncovered grams at the install default. When no Spoolman roll can be priced, the archive retains its prior estimate. Archive-level rates represent a full print. A failed reprint must retain its own run cost without replacing a successful first print's figure. Recalculate Costs can reprice recorded usage for extant rolls and adjust matching run costs. A deleted roll keeps its recorded cost. [Archive pricing](../../bambuddy/backend/app/services/print_cost_estimate.py) · [Remote pricing](../../bambuddy/backend/app/services/spoolman_tracking.py) · [Historical repricing](../../bambuddy/backend/app/services/usage_repricing.py)

## Forecasts, buying, labels and portability

**Low stock and reorder timing.** A single spool's low-stock percentage uses a per-roll override or the global threshold (20% by default). The forecast answers a different question for all active stock of a SKU. Sum usable grams. Estimate daily consumption from intervals between distinct usage days, with a 30-day half-life. If there are too few days, spread consumption since baseline across the time the rolls were in use, using a 90-day window. Recently archived spools contribute to demand and contribute zero stock. Reorder point in grams is daily rate × lead time + 1.65 × daily-rate deviation × √lead time + the configured margin in days or grams. Use the greater of SKU and global lead times. A stock break takes priority when supply runs out by the time replenishment could arrive. Support per-SKU overrides and snoozed alerts. The browser's forecast and server-side alert calculation should agree on the same history. [Forecast rules](../../bambuddy/backend/app/services/stock_forecast.py) · [Forecast UI](../../bambuddy/frontend/src/components/ForecastPanel.tsx)

**Shopping list.** From a forecast, choose a quantity of spools or a period of demand, supply a note, and track pending, purchased and received entries. Reverting to pending clears the purchase date. The purchase-status endpoint updates the list record. The tagged web UI's receive action separately marks it received, bulk-creates rolls in the native inventory with category `Stock`, and removes the list item. These are separate requests. A port aiming for retry-safe receipt should explicitly associate an inventory receipt with its purchase and select the intended inventory backend. [Shopping list](../../bambuddy/backend/app/models/shopping_list.py) · [Receive action](../../bambuddy/frontend/src/components/ForecastPanel.tsx) · [Native creation endpoint used by the UI](../../bambuddy/frontend/src/api/client.ts)

**Printed labels and scan targets.** Select rolls from either inventory, choose fields and color/monochrome, preview, and export PDF, a single PNG, or a ZIP for multiple images. The tag ships 74×33 mm and 75×55 mm AMS labels, 40×30 mm and 62×29 mm box labels, Avery 5160 and L7160 sheets, and custom saved sheet layouts. Sheet output accepts a starting position on the first page. PNG supports 203, 300 and 600 dpi. The request limit is 500 rolls, with an additional pages × dpi ceiling of 15,000 for rasterized sheets. QR payloads use the configured external URL or the request origin and link to `/inventory?spool=<id>`. The scan-to-location tool pairs a physical shelf or AMS slot with a scanned spool. It also recognizes Spoolman-format labels in that mode. [Renderer](../../bambuddy/backend/app/services/label_renderer.py) · [Route contracts](../../bambuddy/backend/app/api/routes/labels.py) · [Custom layouts](../../bambuddy/backend/app/api/routes/label_templates.py) · [QR assignment](../../bambuddy/frontend/src/utils/qrAssignTarget.ts)

**Inventory CSV.** Export active native rolls. Import previews per-row errors, skips and warnings, resolves color metadata, and commits valid rows together on confirmation. A duplicate-product warning still permits multiple identical rolls. Explicit unused IDs can survive a transfer, preserving printed labels. IDs at or below the previously allocated high-water mark receive new numbers. If an otherwise valid unused ID appears twice in one file, the first valid row keeps it and the later row receives a new one. CSV transfers spool data. A whole-instance migration also needs history, assignments, profiles and other relationships from backup. Spoolman-mode inventory delegates its CSV transfer to Spoolman. [CSV parsing and ID allocation](../../bambuddy/backend/app/services/spool_csv.py) · [Import and export](../../bambuddy/backend/app/api/routes/inventory.py) · [Inventory guide](https://wiki.bambuddy.cool/features/inventory/)

## Drying and SpoolBuddy

**Drying.** A manual request names a printer, AMS unit, material, temperature, integer hours and optional rotation. The delayed form accepts 45–85 °C and 1–24 hours, with an optional future earliest start. Pending work can wait for availability. Recheck model, firmware and reported AMS interlocks before issuing a command. Distinguish a temporary busy state, required power or filament retraction, unsupported hardware and a command accepted without drying actually starting. Scheduled rows reach running, completed, cancelled or failed. Failed rows stay visible until dismissed. The queue and ambient automations have separate enablement. Operator policies cover waiting for a cycle, sustained humidity, and concurrent drying on supported printer/firmware combinations. Mixed materials in a unit require the lowest applicable temperature, longest duration and most sensitive humidity threshold. [Scheduled drying](../../bambuddy/backend/app/api/routes/scheduled_dryings.py) · [Preflight](../../bambuddy/backend/app/services/drying_preflight.py) · [Drying scheduler](../../bambuddy/backend/app/services/print_scheduler.py) · [AMS guide](https://wiki.bambuddy.cool/features/ams/)

On cycle end, stamp the rolls assigned to that unit with their last-dried time, known target temperature and actual known hours. A cycle with five minutes or less left on its final countdown qualifies, as does a cycle that ran at least half of its expected duration. A short aborted cycle preserves the previous drying record. Unknown elapsed time stays unknown if the server joined mid-cycle. Entering a date manually for an external dryer clears the inferred temperature and duration. These fields move with the physical roll between slots and storage. [Drying record rules](../../bambuddy/backend/app/services/spool_drying.py) · [Drying tests](../../bambuddy/backend/tests/integration/test_spool_drying_2863.py)

**Station.** SpoolBuddy is a Raspberry Pi daemon and a touch-oriented web client at `/spoolbuddy`. The Pi can connect to a remote Bambuddy instance or share its host. A hardware adapter reads the PN5180 NFC reader and NAU7802 scale. Registration conveys a stable device ID and capabilities. Heartbeats report health, uptime and system stats and collect pending operations and settings. The daemon defaults to a 10-second heartbeat. The server applies a 30-second offline threshold. Device-scoped events carry scans, removals, scale readings, command results and write outcomes to the kiosk. The main application can inspect or unregister devices and manage updates and diagnostics. [Daemon](../../bambuddy/spoolbuddy/daemon/main.py) · [Device routes](../../bambuddy/backend/app/api/routes/spoolbuddy.py) · [Deployment guide](https://wiki.bambuddy.cool/spoolbuddy/deployment-modes/)

The kiosk exposes Dashboard, AMS, Write Tag, Inventory and Settings. An operator can select a printer, look up a roll by NFC, link an unknown tag, create stock from tag metadata, assign a slot, weigh a spool, adjust display settings, run diagnostics or acknowledge a cleared plate. Calibration uses an empty-scale tare and a known reference weight. Raw weight readings update the display. Updating native stock from a weighing uses `net = max(0, gross − tare)` and `used = max(0, label − net)`, records the weighing and sets the weight lock. Spoolman receives the net remaining weight and a fallback-tare warning when applicable. [Kiosk pages](../../bambuddy/frontend/src/pages/spoolbuddy/) · [Server weighing logic](../../bambuddy/backend/app/api/routes/spoolbuddy.py) · [Kiosk guide](https://wiki.bambuddy.cool/spoolbuddy/usage/)

Reading Bambu tags and writing a custom tag are distinct operations. The writer stages a request for a spool and device, waits for a compatible writable tag, and receives a write result before publishing success. NTAG215/216 use OpenTag3D 2.004 and the smaller NTAG213 uses version 1.000. Track physical write failure, cancellation and successful write with failed inventory linkage separately. A successful hardware write can still require correcting a link in Spoolman. [Encoding](../../bambuddy/backend/app/services/opentag3d.py) · [Write and link outcomes](../../bambuddy/backend/app/api/routes/spoolbuddy.py) · [Device configuration](https://wiki.bambuddy.cool/spoolbuddy/configuration/)

## Budget authorization and settlement

**Accounts and authority.** Billing is optional. The install configures one reporting currency. Each user gets a wallet and an active private cost center. Administrators can set its budget, including zero. Shared centers have memberships with individual print rights. Administration includes creating or deactivating shared centers, assigning members, setting budgets, editing or voiding entries, manual print charges, deposits, withdrawals and rebuilding wallet balances. A shared center with live ledger entries or active reservations cannot be deleted. A personal balance sums the user's nonvoided unassigned transactions and their own private-center transactions. Shared spending belongs to that center. A negative wallet balance alone never refuses a print. [Finance defaults](../../bambuddy/backend/app/services/finance_defaults.py) · [Wallet calculation](../../bambuddy/backend/app/services/finance_balance.py) · [Administration](../../bambuddy/backend/app/api/routes/finance.py)

**Admission.** A billable queued job requires an active cost center, an authorized actor and a positive server-computed estimate. A non-admin needs ownership of the private center or a shared membership with `can_print`. A queue-capable API key can list its owner's centers via `GET /api/v1/finance/cost-centers/mine`. A legacy ownerless key gets an empty list. The interactive ledger and administration have separate user permissions. A center has an unlimited, lifetime, or monthly budget. A monthly reset has a local timezone and a day from 1–31, clamped to the last day of short months. Available budget is the limit less nonvoided debit spending in that window and less outstanding commitments. Deposits can improve a wallet balance without increasing a spending limit. [Budget arithmetic](../../bambuddy/backend/app/services/finance_budget.py) · [Finance routes](../../bambuddy/backend/app/api/routes/finance.py) · [Operator guide](https://wiki.bambuddy.cool/features/billing/)

**Reservations and batch work.** Queuing counts the cost of all accepted copies. The pending item's estimate acts as the commitment until dispatch replaces it with an explicit reservation. During an edit or recheck, exclude that item's own hold. Count each still-pending plate separately even if several share an archive. The scheduler rechecks cost, budget and permission before sending the print. A failed start releases its unconfirmed reservation. Cancellation releases the relevant commitment. When dispatching missing copies of an order, group the new copies by their template's cost center and validate their combined cost against the dispatcher's rights. An owed replacement is a new attempt that can use material and incur a charge. [Queue creation and copy validation](../../bambuddy/backend/app/api/routes/print_queue.py) · [Dispatch reservation](../../bambuddy/backend/app/services/print_scheduler.py) · [Batch intent](../../bambuddy/backend/app/models/print_batch.py) · [Reservation tests](../../bambuddy/backend/tests/integration/test_scheduler_budget_reservation.py)

**Cost at v.1.3.2.** A browser estimate is a display hint. For an archive queue item the server uses positive stored archive cost, scaled by selected plate grams over whole-file grams when the plate source is available. If the archive has only grams it uses the install default. For a library file, price its per-slot grams at the mapped spool rates when available and fall back to the default. Variant submissions use the highest known variant estimate if all variants can be priced. For wallet settlement the completion path captures the archive/plate baseline *before* completion writes measured usage. A completed run owes the full baseline. A failed, cancelled or aborted run owes `baseline × clamp(consumed/planned, 0, 1)`, rounded to two decimal places. Without a reliable positive planned amount the proportional charge is zero. This release's wallet charge is for filament. The print log can separately store energy and wear. [Trusted queue estimator](../../bambuddy/backend/app/services/print_cost_estimate.py) · [Completion ordering](../../bambuddy/backend/app/main.py) · [Settlement rules](../../bambuddy/backend/app/services/finance_billing.py)

**One debit per run.** Each dispatch has its own billing run ID. Persist it before commanding the printer, then associate the final debit with that run, its queue item and its cost center. Repeated completion reports must converge on the existing transaction. Voiding a charge leaves an invisible run-keyed record so a late completion cannot recreate it. A reprint has a new run ID. Charge the queueing user even when someone else owns the archive. If that user is deleted mid-print, a surviving center still bears the charge with a null user. Consume the matching reservation only when the transaction succeeds, or release it when nothing is due or billing is disabled. Charge failures raise an operator-visible event and configured provider alert. [Ledger data model](../../bambuddy/backend/app/models/finance.py) · [Wallet charge service](../../bambuddy/backend/app/services/finance_billing.py) · [Deleted-user tests](../../bambuddy/backend/tests/unit/services/test_finance_billing_deleted_user.py)

**Direct-to-printer work.** With both billing and the printer kill switch enabled, the server can cancel a print positively identified as outside Bambuddy's dispatch, record cancellation and notify the operator. It acts after observing a start. An uncertain run just after reconnect or restart can be deferred. Built-in calibration is exempt when firmware reports a reliably identifiable calibration path. Models reporting only an ordinary filename cannot use that exemption. ## Worked parity cases

| Given a clean fixture | Expected result in the tagged release |

## Differences in the living wiki

The current wiki describes pricing billable runs at the spools loaded at start, admitting explicitly free native spools, and operator policies for charging energy, wear or full/zero filament on failures. The tagged budget validator requires a positive estimate, and its settlement code applies the archive/plate filament formula above. Treat the newer policies as a separate parity target. The wiki also describes multi-filament automatic backup attribution when the changed filament can be proven. In the tag, cross-tray backup splitting requires a single used filament. Same-tray manual spool replacement has its own tracking.
